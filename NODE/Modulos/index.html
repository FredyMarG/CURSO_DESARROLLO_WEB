DIAPOSITIVA 2 · CONCEPTO BASE

¿Qué es un Módulo y Para Qué Sirve?

Un módulo es un archivo o unidad de código que encapsula una responsabilidad y expone funciones, constantes, clases u objetos para reutilizarlos desde otros archivos.

  • Exportar: hacer disponible un valor hacia otros módulos.
  • Importar: utilizar desde otro archivo un valor exportado.
  • Encapsular: mantener detalles internos fuera de la API pública del módulo.
  • Beneficios: organizar proyectos grandes, reutilizar lógica, facilitar pruebas (node --test) y mejorar el mantenimiento.
🧱 Analogía LEGO y departamentos: Cada módulo es una pieza con conexiones definidas (como ventas o contabilidad en una empresa): puedes reemplazar una pieza sin reconstruir toda la aplicación.

DIAPOSITIVA 4 · EXPORTAR E IMPORTAR EN COMMONJS

CommonJS: module.exports y require()

En CommonJS (por defecto si package.json usa "type": "commonjs" o en archivos .cjs), cada archivo es un módulo privado hasta que expones valores con module.exports y los consumes en otro archivo con require("./ruta.js"). 

// 1. Exportar múltiples funciones desde saludo.js
function saludar(nombre) { return `Hola ${nombre}`; }
function despedir(nombre) { return `Hasta pronto, ${nombre}`; }
module.exports = { saludar, despedir };

// 2. Exportar una única función directamente
module.exports = function saludarUno(nombre) { return `Hola, ${nombre}`; };

// 3. Importar en app.js (desestructuración o valor directo)
const { saludar, despedir } = require("./saludo.js");
console.log(saludar("Heidy")); // Hola Heidy
  • exports.saludar = ... funciona porque apunta al mismo objeto que module.exports.
  • ¡Cuidado! Reasignar exports = { ... } rompe esa referencia y no exporta el objeto.
DIAPOSITIVA 5 · EXPORTAR E IMPORTAR EN ESM

ESM: export e import entre Archivos

Para usar el estándar moderno ESM en archivos .js, configura "type": "module" en package.json (o usa extensión .mjs). Al importar archivos locales en Node.js debes incluir siempre la extensión (.js). 

// archivo: matematicas.js (exportar funciones, constantes o clases)
export function sumar(a, b) { return a + b; }
export const PI = 3.14159;

// archivo: app.js (importar desde otro archivo en la misma carpeta)
import { sumar, PI } from "./matematicas.js";
console.log(sumar(5, 7), PI); // 12 3.14159
DIAPOSITIVA 6 · PATRONES DE EXPORTACIÓN E IMPORTACIÓN

Exportaciones Nombradas vs Por Defecto

// Exportación nombrada: puedes exportar muchas y renombrarlas al importar con "as"
export const rol = "estudiante";
export function crearUsuario(nombre) { return { nombre, rol }; }
import { crearUsuario as registrar } from "./usuario.js";

// Exportación por defecto: máximo 1 por archivo; quien importa elige el nombre
export default function formatear(texto) { return texto.trim().toUpperCase(); }
import formatearTexto from "./formatear.js";

// Importar todas las exportaciones nombradas bajo un objeto espacio de nombres
import * as operaciones from "./matematicas.js";
console.log(operaciones.sumar(2, 3));

DIAPOSITIVA 10 · COMPORTAMIENTO AVANZADO

import() Dinámico, Caché y import.meta.url

  • Importación dinámica: await import("./reportes.mjs") carga un módulo bajo demanda devolviendo una Promesa.
  • Caché de módulos: Node.js evalúa el módulo una vez y reutiliza su instancia; para estados independientes exporta una función fábrica.
  • Ruta del archivo en ESM: usa fileURLToPath(import.meta.url) y path.dirname() como alternativa portable a __dirname.
// 1. Importación dinámica bajo demanda
async function cargarReporte() {
  const { generarReporte } = await import("./reportes.mjs");
  return generarReporte();
}

// 2. Evitar estado compartido usando una función fábrica
export function crearContador() {
  let total = 0;
  return { incrementar: () => ++total, leer: () => total };
}

// 3. Equivalente a __dirname / __filename en ESM
import { fileURLToPath } from "node:url";
import path from "node:path";
const __filename = fileURLToPath(import.meta.url);
const __dirname = path.dirname(__filename);
