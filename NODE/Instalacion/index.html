DIAPOSITIVA 2 · ELECCIÓN DE VERSIÓN

¿LTS o Current? ¿Cuál Instalar?

AspectoLTS (Long Term Support)Current (Actual)
EstabilidadAlta, pensada para producciónExperimental, cambia rápido
SoporteLargo plazo (~30 meses)Corto plazo
Uso recomendadoCursos, empresas y servidoresProbar funciones muy nuevas
✅ Regla de oro: Instala siempre la versión LTS (números pares como 20.x, 22.x o 24.x) para evitar incompatibilidades.
DIAPOSITIVA 3 · MÉTODOS DIRECTOS

Instalar en Windows: .msi o winget

  • Opción 1 (Instalador oficial): descarga el .msi LTS desde nodejs.org, deja marcada la casilla Add to PATH y reinicia tu terminal.
  • Opción 2 (PowerShell con winget): instala Node.js LTS con un solo comando:
# Instalar Node.js LTS usando winget
winget install OpenJS.NodeJS.LTS
DIAPOSITIVA 4 · GESTOR DE VERSIONES

Cambiar de Versión con nvm-windows

Si trabajas en varios proyectos que requieren distintas versiones de Node.js, usa nvm-windows: 

# Listar versiones disponibles para descargar
nvm list available

# Instalar la última versión LTS
nvm install lts

# Activar una versión específica
nvm use 22.14.0

# Ver versiones instaladas y cuál está activa (*)
nvm list
DIAPOSITIVA 5 · COMPROBACIÓN

Verificar node, npm y el PATH

# Comprobar versiones instaladas y ruta exacta del binario
node -v
npm -v
where.exe node
  • Si aparece "'node' no se reconoce como un comando...", cierra y vuelve a abrir VS Code o PowerShell.
  • Si persiste, revisa en Windows que C:\Program Files\nodejs\ esté en las Variables de entorno → Path.
DIAPOSITIVA 6 · ERROR TÍPICO EN WINDOWS

Solucionar Bloqueo de Scripts en PowerShell

Si PowerShell muestra "la ejecución de scripts está deshabilitada en este sistema" al ejecutar npm, habilita scripts firmados localmente para tu usuario actual: 

# Consultar la política actual
Get-ExecutionPolicy -Scope CurrentUser

# Permitir scripts locales y paquetes npm de forma segura
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
DIAPOSITIVA 7 · FLUJO DE TRABAJO

VS Code, node --watch y .gitignore

// package.json con recarga automática nativa (--watch)
{
  "name": "entorno-node",
  "version": "1.0.0",
  "private": true,
  "scripts": {
    "start": "node index.js",
    "dev": "node --watch index.js"
  }
}
  • node --watch reinicia el proceso automáticamente al guardar cambios (sin instalar nodemon).
  • Crea un archivo .gitignore con node_modules/ y .env para proteger dependencias y secretos.
