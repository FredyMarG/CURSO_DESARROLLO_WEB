DIAPOSITIVA 2 · ENTORNO Y CONFIGURACIÓN

node:process, process.env y .env Nativo

process es una instancia de EventEmitter que conecta tu código JavaScript con el sistema operativo. Con process.env lees puertos, modos y secretos (siempre llegan como string), y desde Node 20.6+ cargas .env sin instalar dotenv: 

// Opción 1 (CLI): node --env-file=.env src/server.js
// Opción 2 (código, Node 21.7+ / 22+):
import process from 'node:process';
process.loadEnvFile();

const PORT = Number(process.env.PORT) || 3000;
const MODO = process.env.NODE_ENV ?? 'development';
DIAPOSITIVA 3 · ARGUMENTOS CLI PROFESIONALES

process.argv y parseArgs() de node:util

process.argv entrega los argumentos crudos de consola (los del usuario empiezan en el índice 2). En lugar de analizar flags a mano con if, Node.js incluye parseArgs() en node:util: 

import process from 'node:process';
import { parseArgs } from 'node:util';

// Ej: node cli.js --port 4000 --watch tareas.json
const { values, positionals } = parseArgs({
  args: process.argv.slice(2),
  options: {
    port: { type: 'string', short: 'p', default: '3000' },
    watch: { type: 'boolean', short: 'w', default: false }
  },
  allowPositionals: true
});
DIAPOSITIVA 4 · CANALES ESTÁNDAR DEL SO

Streams Estándar: stdin, stdout y stderr

Todo proceso se comunica mediante tres streams estándar. De hecho, console.log() escribe en process.stdout y console.error() escribe en process.stderr:

StreamTipoPara qué sirve
process.stdinReadableLeer texto del teclado o datos encadenados con |
process.stdoutWritableSalida normal del programa (datos y resultados)
process.stderrWritableMensajes de error o diagnóstico separados del flujo normal
DIAPOSITIVA 5 · FINALIZACIÓN SEGURA

Por qué Usar process.exitCode = 1 en vez de process.exit(1)

Llamar a process.exit(1) detiene Node.js de forma abrupta e inmediata: puede cortar mensajes en stdout o dejar archivos a medio escribir. Asignar process.exitCode = 1 deja que el Event Loop termine lo pendiente antes de salir: 

try {
  await ejecutarMigracion();
} catch (err) {
  console.error('Error:', err.message);
  process.exitCode = 1; // ✅ Sale con código 1 cuando acabe la E/S pendiente
}
DIAPOSITIVA 6 · PRODUCCIÓN Y CONTENEDORES

Señales SIGINT, SIGTERM y Cierre Limpio

Al pulsar Ctrl + C llega SIGINT; cuando Docker o la nube detienen tu servidor llega SIGTERM. Escuchar ambas permite cerrar el servidor HTTP sin cortar peticiones activas: 

function cerrarLimpiamente(senal) {
  console.log(`Señal ${senal}: cerrando servidor...`);
  server.close(() => {
    console.log('Peticiones activas finalizadas.');
    process.exitCode = 0;
  });
}
process.on('SIGINT', () => cerrarLimpiamente('SIGINT'));
process.on('SIGTERM', () => cerrarLimpiamente('SIGTERM'));
DIAPOSITIVA 7 · ÚLTIMA LÍNEA DE DEFENSA

Eventos Globales: uncaughtException y unhandledRejection

Si un error escapa a todos los try/catch, estos eventos permiten registrarlo antes de morir. Regla crítica: tras un uncaughtException no sigas operando normalmente porque la memoria puede estar inconsistente; registra el fallo y cierra el proceso. 

process.on('unhandledRejection', (razon) => {
  console.error('Promesa sin catch:', razon);
  process.exitCode = 1;
});
process.on('uncaughtException', (err) => {
  console.error('Fallo crítico no capturado:', err);
  process.exit(1); // Aquí sí conviene reiniciar mediante PM2/Docker
});

DIAPOSITIVA 10 · INTERACCIÓN POR TUBERÍAS (PIPES)

Leer Datos desde process.stdin con for await

Como process.stdin es un Readable Stream, puedes iterarlo con for await...of tanto para preguntar datos en terminal como para recibir datos encadenados desde Bash (cat datos.txt | node app.js): 

import process from 'node:process';

process.stdout.write('Escribe tu nombre: ');
for await (const chunk of process.stdin) {
  process.stdout.write('Hola, ' + chunk.toString().trim() + '\n');
  break;
}
