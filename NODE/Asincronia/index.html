DIAPOSITIVA 2 · MOTOR Y COORDINACIÓN

V8, Event Loop y Prioridad de Colas

  • V8: compila y ejecuta JavaScript y gestiona la memoria, pero no incluye APIs del sistema como node:fs.
  • Event Loop: ejecuta JavaScript en un hilo principal y delega E/S al sistema operativo o a libuv.
  • Orden estricto: primero código síncrono, luego microtareas (Promise.then) y después temporizadores (setTimeout).
console.log('A: inicio');
setTimeout(() => console.log('D: temporizador'), 0);
Promise.resolve().then(() => console.log('C: promesa'));
console.log('B: fin síncrono');
// Salida: A: inicio -> B: fin síncrono -> C: promesa -> D: temporizador
⚠️ Bloqueo del hilo: Un bucle pesado como while (Date.now() - inicio < 300) {} congela todo el Event Loop e impide atender otras peticiones.
DIAPOSITIVA 3 · PATRÓN CLÁSICO

Callbacks Síncronos, Asíncronos y Error-First

Un callback es una función pasada a otra para ejecutarse después o al ocurrir un evento. No todo callback es asíncrono (por ejemplo, array.map(cb) es síncrono). 

import fs from 'node:fs';

// Patrón habitual de Node.js: (error, resultado)
fs.readFile('curso.json', 'utf8', (error, contenido) => {
  if (error) {
    console.error('No se pudo leer:', error.code); // Ej: ENOENT
    return;
  }
  console.log(contenido);
});
DIAPOSITIVA 4 · ESTADOS Y COMBINADORES

Promesas: all, allSettled y race

CombinadorComportamientoCuándo usarlo
Promise.all()Espera todas; rechaza inmediatamente si una fallaTodas las tareas son obligatorias para continuar
Promise.allSettled()Espera todas y reporta éxitos (fulfilled) y fallos (rejected)Cuando se admiten fallos parciales (ej. lotes o reportes)
Promise.race()Adopta la primera promesa que se resuelva o rechaceTimeouts o competir entre réplicas
 
const resultados = await Promise.allSettled([
  ejecutarTarea('Cargar cursos', 300),
  ejecutarTarea('Generar reporte', 200, true)
]);
// Ningún fallo oculta el resultado de las demás tareas
DIAPOSITIVA 5 · SINTAXIS MODERNA

async/await, try/catch y Secuencial vs Concurrente

const esperar = ms => new Promise(resolve => setTimeout(resolve, ms));

async function comparar() {
  // ❌ Secuencial innecesario (~200 ms)
  await esperar(100);
  await esperar(100);

  // ✅ Concurrente (~100 ms): esperas independientes se superponen
  await Promise.all([esperar(100), esperar(100)]);
}
✅ Manejo de errores: Envuelve tus llamadas await en bloques try / catch para capturar rechazos de forma clara y evitar promesas sin manejar.
DIAPOSITIVA 6 · CALIDAD Y DEPURACIÓN

Buenas Prácticas y Errores Frecuentes

Buena prácticaError que evita
Usar try/catch con awaitRechazos de promesas sin manejar
Elegir Promise.allSettled en lotesPerder el reporte de tareas exitosas si una falla
Validar entradas antes de iniciar tareasErrores difíciles de diagnosticar
Evitar bucles CPU-intensivos en el hilo principalBloquear el Event Loop del servidor
  • forEach(async ...): forEach no espera promesas; usa for...of (secuencial) o Promise.all(arr.map(...)) (concurrente).
  • Olvidar await: asigna una Promise { <pending> } en lugar del valor resuelto.
