DIAPOSITIVA 2 · TESTING SIN DEPENDENCIAS

¿Por qué Usar node:test y node:assert/strict?

Node.js incluye su propio corredor de pruebas nativo. Ejecuta archivos *.test.js en paralelo, soporta ES Modules y async/await sin configurar Babel ni instalar cientos de paquetes: 

import test from 'node:test';
import assert from 'node:assert/strict';

test('calcula el total con IVA incluido', () => {
  const total = 100 * 1.19;
  assert.equal(total, 119);
});
// En consola: node --test  |  Modo continuo: node --test --watch
DIAPOSITIVA 3 · COMPARACIONES SEGURAS

equal vs deepEqual vs ok

Importa siempre node:assert/strict (nunca el modo antiguo no estricto) para evitar que 1 == '1' pase por válido. Usa cada aserción según el tipo de dato:

AserciónCuándo usarlaEjemplo
assert.equal(a, b)Números, strings y booleanosassert.equal(res.status, 200)
assert.deepEqual(a, b)Objetos y arreglos por contenidoassert.deepEqual(lista, [1, 2])
assert.ok(val)Comprobar que existe o es verdaderoassert.ok(tarea.id)
DIAPOSITIVA 4 · VALIDACIÓN DE FALLOS

assert.throws() vs assert.rejects()

Probar solo el "camino feliz" no basta: debes verificar que tus validaciones rechacen entradas inválidas. Usa throws para funciones síncronas y await assert.rejects() para funciones async: 

// 1) Síncrono: pasa una función envolvente () => ...
assert.throws(() => validarEdad(-5), RangeError);

// 2) Asíncrono: espera la promesa con await
await assert.rejects(
  () => crearTarea('   '),
  (err) => err.code === 'validation'
);
DIAPOSITIVA 5 · ORGANIZACIÓN DE PRUEBAS

Suites (describe/it) y Hooks (beforeEach)

Cuando un archivo prueba muchas funciones de un mismo módulo, agrúpalas con describe() e it() y reinicia datos compartidos antes de cada prueba con beforeEach(): 

import { describe, it, beforeEach } from 'node:test';
import assert from 'node:assert/strict';

describe('Repositorio en memoria', () => {
  let db;
  beforeEach(() => { db = []; });

  it('inicia vacío y agrega 1 elemento', () => {
    db.push({ id: 1 });
    assert.equal(db.length, 1);
  });
});
DIAPOSITIVA 6 · ARCHIVOS TEMPORALES

Aislar Pruebas de Disco con mkdtemp() y t.after()

Nunca ensucies tus archivos reales en data/ al correr tests. Crea una carpeta temporal única en os.tmpdir() y bórrala automáticamente al terminar la prueba con t.after(): 

test('escribe sin tocar data/ real', async (t) => {
  const dir = await mkdtemp(path.join(os.tmpdir(), 'app-test-'));
  t.after(() => rm(dir, { recursive: true, force: true }));

  const ruta = path.join(dir, 'tareas.json');
  await writeFile(ruta, '[]', 'utf8');
  assert.equal(await readFile(ruta, 'utf8'), '[]');
});
DIAPOSITIVA 7 · SIMULACIÓN DE DEPENDENCIAS

Espías y Mocks Nativos con t.mock.fn()

Si quieres verificar que una función llamó a un servicio externo (ej. enviar un email) sin enviarlo de verdad durante el test, usa t.mock.fn() e inspecciona mock.callCount() y mock.calls: 

test('envía bienvenida 1 vez', (t) => {
  const enviarEmail = t.mock.fn((to) => `OK:${to}`);
  registrarUsuario('ana@dev.io', enviarEmail);

  assert.equal(enviarEmail.mock.callCount(), 1);
  assert.deepEqual(enviarEmail.mock.calls[0].arguments, ['ana@dev.io']);
});
DIAPOSITIVA 8 · ESTRUCTURA Y MÉTRICAS

Patrón AAA y Cobertura Nativa de Código

Toda prueba clara sigue tres pasos: Arrange (preparar datos), Act (ejecutar) y Assert (comprobar). Además, Node.js mide qué porcentaje de tu código cubren los tests: 

# Ejecutar todas las pruebas con reporte de cobertura nativo
node --test --experimental-test-coverage

DIAPOSITIVA 10 · TESTS INSTANTÁNEOS

Simular Relojes y setTimeout con t.mock.timers

Si una función expira un token tras 60 segundos, no quieres que tu test tarde 60 segundos reales. Con t.mock.timers adelantas el reloj virtual al instante: 

test('expira el token tras 60s al instante', (t) => {
  t.mock.timers.enable({ apis: ['setTimeout'] });
  let expirado = false;
  setTimeout(() => { expirado = true; }, 60_000);
  t.mock.timers.tick(60_000); // Avanza 60s virtuales en 0 ms
  assert.equal(expirado, true);
});
