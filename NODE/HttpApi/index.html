DIAPOSITIVA 2 · SERVIDOR NATIVO

Anatomía de http.createServer(req, res)

Todo framework como Express o Fastify se apoya sobre node:http. En cada petición recibes req (un Readable Stream con método, URL y cabeceras) y res (un Writable Stream para responder): 

import http from 'node:http';

const server = http.createServer((req, res) => {
  res.writeHead(200, { 'Content-Type': 'application/json; charset=utf-8' });
  res.end(JSON.stringify({ metodo: req.method, url: req.url }));
});

server.listen(3000, () => console.log('API lista en :3000'));
DIAPOSITIVA 3 · ENRUTAMIENTO MODERNO

Rutas y Query Params con new URL()

Evita cortar req.url a mano con split('?'). La clase global URL separa limpiamente la ruta base (pathname) de los parámetros de consulta (searchParams): 

const url = new URL(req.url || '/', `http://${req.headers.host || 'localhost'}`);
const { pathname, searchParams } = url;

// Ej: GET /api/cursos?nivel=node&limite=5
const nivel = searchParams.get('nivel');         // "node"
const limite = Number(searchParams.get('limite')) || 10;
DIAPOSITIVA 4 · STREAMS DE ENTRADA

Leer el Cuerpo POST/PATCH por Chunks

En node:http el cuerpo JSON no llega en una sola variable: llega en fragmentos por el stream req. Debes juntarlos imponiendo un límite máximo (ej. 1 MB) para proteger la memoria del servidor: 

function leerBodyJson(req, maxBytes = 1e6) {
  return new Promise((resolve, reject) => {
    let raw = '';
    req.on('data', (chunk) => {
      raw += chunk;
      if (raw.length > maxBytes) { req.destroy(); reject(new Error('Payload > 1MB')); }
    });
    req.on('end', () => {
      try { resolve(raw ? JSON.parse(raw) : {}); }
      catch { reject(new Error('JSON inválido')); }
    });
  });
}

Métodos REST y Códigos de Estado Semánticos

Una API REST usa el mismo recurso (/api/tareas) y distingue la acción mediante el método HTTP y el código numérico de respuesta:

OperaciónMétodo + RutaCódigo

Crear recursoPOST /api/tareas201 Created (o 400 si inválido)
Actualizar parcialPATCH /api/tareas/:id200 OK (o 404)

DIAPOSITIVA 6 · CONEXIÓN DESDE EL NAVEGADOR

CORS (Cross-Origin) y Preflight OPTIONS

Si tu frontend corre en otro puerto (ej. :5500) y llama a tu API Node.js (:3000), el navegador exige cabeceras Access-Control-Allow-* y envía antes una petición de permiso OPTIONS: 

const CORS = {
  'Access-Control-Allow-Origin': '*',
  'Access-Control-Allow-Methods': 'GET,POST,PATCH,DELETE,OPTIONS',
  'Access-Control-Allow-Headers': 'Content-Type'
};
if (req.method === 'OPTIONS') { res.writeHead(204, CORS); return res.end(); }
DIAPOSITIVA 7 · SEGURIDAD EN SERVIDORES

Servir Estáticos y Proteger contra Path Traversal

Si tu servidor entrega archivos HTML/CSS/JS desde una carpeta public/, valida siempre que la ruta resuelta empiece por PUBLIC_DIR para impedir que un cliente lea archivos del sistema con ../../: 

const ruta = path.resolve(PUBLIC_DIR, relPath);
if (!ruta.startsWith(PUBLIC_DIR)) {
  res.writeHead(403);
  return res.end('Acceso denegado');
}
DIAPOSITIVA 8 · TESTING DE ENDPOINTS

Probar tu API en Puerto Efímero (listen(0)) + fetch()

En tus tests automáticos usa server.listen(0) para que el sistema asigne un puerto libre automáticamente, consulta con fetch() y cierra con t.after(() => server.close()): 

await new Promise((r) => server.listen(0, '127.0.0.1', r));
t.after(() => server.close());
const { port } = server.address();
const res = await fetch(`http://127.0.0.1:${port}/api/tareas`);
assert.equal(res.status, 200);
⏱️ Timeout seguro en backend: usa fetch(url, { signal: AbortSignal.timeout(5000) }) para evitar que una API externa lenta bloquee tu servidor.

DIAPOSITIVA 10 · ROBUSTEZ EN PRODUCCIÓN

Mapear Errores de Negocio a Códigos HTTP (400, 404, 500)

Si tu capa de negocio etiqueta errores con error.code ('validation', 'not_found'), el servidor HTTP los traduce en un único catch central sin repetir bloques de respuesta en cada ruta: 

const STATUS_POR_CODIGO = { validation: 400, not_found: 404, unauthorized: 401 };
// Dentro del catch principal de createServer:
const status = STATUS_POR_CODIGO[error.code] || 500;
enviarJson(res, status, { error: error.message });
⚠️ Error clásico ERR_HTTP_HEADERS_SENT: ocurre al intentar enviar cabeceras o llamar res.end() dos veces. Usa siempre return res.end(...) tras responder.
