DIAPOSITIVA 2 · DEFINICIÓN Y CREACIÓN

¿Qué es RegExp? Literal vs Constructor

Una expresión regular describe un patrón de texto. Usa la forma literal cuando el patrón es fijo (se compila una vez al cargar) y new RegExp() solo cuando necesitas armar el patrón desde una variable: 

const fijo = /^[a-z0-9]+$/i; // Recomendado si no cambia
const palabra = 'node';
const dinamico = new RegExp(`\\b${palabra}\\b`, 'gi'); // Nota: escapa "\\" en strings
DIAPOSITIVA 3 · MODIFICADORES DE BÚSQUEDA

Banderas Esenciales: g, i, m y u

Las banderas se colocan al final del patrón y cambian cómo el motor busca coincidencias:

FlagEfectoEjemplo
gGlobal: encuentra todas las coincidencias, no solo la 1.ª'a1b2'.match(/\d/g) → ['1','2']
iIgnora mayúsculas y minúsculas/node/i.test('NODE') → true
mMultilínea: ^ y $ aplican a cada línea/^error/gm
uSoporte Unicode completo (acentos y emojis)/\p{L}+/gu
DIAPOSITIVA 4 · COMODINES Y RANGOS

Clases de Caracteres: \d, \w, \s y Corchetes

En minúscula buscan el carácter; en MAYÚSCULA (\D, \W, \S) buscan exactamente lo contrario:

PatrónCoincide con
\d / \DDígito (0–9) / Cualquier carácter que NO sea dígito
\w / \WLetra ASCII, número o _ / Símbolos y espacios
\s / \SEspacio, tabulador o salto / Carácter visible
[a-z] / [^0-9]Rango de letras / Todo excepto números
DIAPOSITIVA 5 · LÍMITES EXACTOS

Anclas: Por Qué ^ y $ Son Obligatorios al Validar

Sin ^ (inicio) y $ (fin), /\d{4}/ devolvería true para "hola1234mundo" porque encontró 4 dígitos en el medio. Para validar todo el texto usa siempre anclas: 

/\d{4}/.test('hola1234mundo');   // true (¡peligro en validaciones!)
/^\d{4}$/.test('hola1234mundo'); // false (exige exactamente 4 dígitos)
/^\d{4}$/.test('2026');          // true
DIAPOSITIVA 6 · REPETICIONES

Cuantificadores: +, *, ? y {n,m}

Los cuantificadores indican cuántas veces puede repetirse el token inmediatamente anterior:

CuantificadorSignificadoEjemplo
+1 o más veces\d+ coincide con "4" y "420"
*0 o más vecesa* coincide con "" y "aaa"
?Opcional (0 o 1 vez)https? coincide con http y https
{n,m}Entre n y m veces\d{2,4} exige 2, 3 o 4 dígitos
DIAPOSITIVA 7 · EXTRAER PARTES DE UN TEXTO

Grupos (...) y Grupos Nombrados (?<nombre>...)

Los paréntesis capturan subcadenas para extraerlas con match(). Con grupos nombrados obtienes directamente un objeto groups muy legible: 

const re = /^(?<anio>\d{4})-(?<mes>\d{2})-(?<dia>\d{2})$/;
const res = '2026-11-25'.match(re);
console.log(res.groups); // { anio: '2026', mes: '11', dia: '25' }
DIAPOSITIVA 8 · APLICACIÓN EN JAVASCRIPT

test(), match(), matchAll() y replace()

Elige el método según si quieres validar, extraer o transformar texto: 

// 1) Validar (booleano)
/^[^\s@]+@[^\s@]+\.[^\s@]{2,}$/.test('ana@dev.io'); // true

// 2) Limpiar espacios múltiples con replace()
'Hola    mundo   JS'.replace(/\s+/g, ' '); // "Hola mundo JS"

// 3) Extraer todas las ocurrencias con grupos usando matchAll()
const tags = [...'#node #js #css'.matchAll(/#(\w+)/g)].map(m => m[1]); // ['node','js','css']
DIAPOSITIVA 9 · BUG MUY FRECUENTE

Cuidado con .test() + Bandera g (lastIndex)

Cuando una expresión regular tiene el flag g, guarda el índice donde quedó (regex.lastIndex). Si la reutilizas con .test(), puede alternar true y false sobre el mismo texto: 

const re = /\d+/g;
console.log(re.test('123')); // true  (lastIndex queda en 3)
console.log(re.test('123')); // false (busca desde índice 3!)
// ✅ Solución: NO uses el flag "g" cuando valides con .test()
DIAPOSITIVA 10 · USO REAL Y SEGURIDAD

Patrones Útiles y Prevención de ReDoS

Evita cuantificadores anidados como (a+)+ (pueden congelar el hilo principal de JS/Node ante entradas maliciosas, ataque llamado ReDoS). Usa patrones simples y acotados:

ValidaciónPatrón seguro
Slug de URL/^[a-z0-9]+(?:-[a-z0-9]+)*$/
Fecha ISO YYYY-MM-DD/^\d{4}-\d{2}-\d{2}$/
Solo dígitos (PIN 4–6)/^\d{4,6}$/
