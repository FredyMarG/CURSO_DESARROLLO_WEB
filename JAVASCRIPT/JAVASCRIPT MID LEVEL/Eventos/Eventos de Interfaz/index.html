DIAPOSITIVA 2 · FUNDAMENTOS

¿Qué son los Eventos de Interfaz?

Son eventos disparados por el navegador ante cambios en la ventana, el scroll, el foco o la carga de recursos:

  • resize: se dispara cuando cambia el tamaño del viewport (window.innerWidth).
  • scroll: ocurre al desplazarse por la página o un contenedor con overflow.
  • select: se activa cuando el usuario selecciona texto dentro de un <input> o <textarea>.
  • error / load: permiten detectar si una imagen o script cargó bien o falló para aplicar un fallback.
🎛️ Analogía del tablero de un auto: No los dispara un clic directo, sino el entorno cambiando: la velocidad (scroll), el tamaño de pantalla (resize) o una alerta de falla (error).
DIAPOSITIVA 3 · SINTAXIS Y PROPIEDADES

Sintaxis y Listeners Pasivos

// Scroll fluido sin bloquear el hilo de renderizado
scrollBox.addEventListener('scroll', () => {
  console.log('scrollTop:', scrollBox.scrollTop);
}, { passive: true });

// Capturar texto seleccionado en un input
input.addEventListener('select', (e) => {
  const texto = e.target.value.slice(e.target.selectionStart, e.target.selectionEnd);
  console.log('Seleccionado:', texto);
});

// Fallback elegante si falla una imagen
img.addEventListener('error', () => {
  img.src = 'fallback.png';
});
Elemento / APIDescripción
selectSelección de texto en input/textarea (selectionStart/End)
resizeCambio de dimensiones de window
scrollDesplazamiento vertical u horizontal (usar { passive: true })
errorFallo al cargar imagen, iframe o recurso externo
DIAPOSITIVA 4 · BUENAS PRÁCTICAS

Consejos y Errores Comunes

✅ Rendimiento en scroll/touch: Usa siempre { passive: true } cuando no vayas a llamar a e.preventDefault(); así el navegador desplaza a 60 FPS sin esperar a tu JavaScript.
⚠️ Cuidado con resize y scroll: Pueden dispararse decenas de veces por segundo. Evita operaciones pesadas en el DOM dentro de estos listeners o usa debounce.
Ciclo de carga

DOMContentLoaded vs load

Saber cuándo el DOM está listo evita errores de Cannot read properties of null:

DOMContentLoaded

Se dispara en document apenas se parsea el HTML y los scripts diferidos, sin esperar imágenes ni CSS externo.

window.load

Espera a que TODAS las imágenes, fuentes, iframes y hojas de estilo terminen de descargarse.

Entrada de datos

Eventos de formulario: input vs change vs submit

  • input: Se dispara instantáneamente en cada tecla, pegado o borrado.
  • change: En textos se dispara solo al perder el foco tras cambiar; en <select> y checkboxes es inmediato.
  • submit: Se escucha en el <form> (no en el botón) y se intercepta con e.preventDefault().
Validación en UI

Eventos de foco: focus, blur, focusin, focusout

focus y blur no burbujean, mientras que focusin y focusout sí lo hacen, permitiendo validar formularios completos desde un solo listener padre.

form.addEventListener('focusout', (e) => {
  if (e.target.matches('input')) validarCampo(e.target);
});
Layout y viewport

scroll, resize y Observers modernos

Aunque window.addEventListener('scroll') y resize siguen siendo útiles, hoy existen APIs dedicadas mucho más eficientes:

  • IntersectionObserver: Detecta si un elemento entra en pantalla (lazy-load, scroll infinito) sin calcular offsets en cada frame.
  • ResizeObserver: Reacciona cuando un contenedor específico cambia de tamaño.
Estado de la pestaña

visibilitychange y beforeunload

document.visibilitychange avisa cuando el usuario cambia de pestaña (document.hidden), ideal para pausar videos o intervalos.

beforeunload permite advertir antes de cerrar si hay cambios sin guardar en un editor.

Resiliencia

Eventos de error en recursos y multimedia

Las etiquetas <img>, <video> y <script> disparan error si falla la red. Puedes mostrar una imagen de respaldo automáticamente:

img.addEventListener('error', () => {
  img.src = '/assets/avatar-fallback.png';
}, { once: true });
