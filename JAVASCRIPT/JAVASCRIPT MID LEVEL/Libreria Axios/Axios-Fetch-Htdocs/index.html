DIAPOSITIVA 2 · FUNDAMENTOS

Comparativa Práctica: Fetch vs Axios

Ambos clientes envían peticiones HTTP asíncronas usando Promesas, pero difieren en ergonomía:

  • Fetch: nativo del navegador; requiere JSON.stringify(), validar if (!res.ok) y llamar a res.json().
  • Axios: librería externa; serializa el objeto en POST, parsea en res.data y rechaza errores 4xx/5xx automáticamente.
⚖️ Analogía manual vs automático: Fetch es conducción manual (tú controlas cada paso); Axios es transmisión automática (se encarga del JSON y los errores HTTP).
DIAPOSITIVA 3 · SINTAXIS Y PROPIEDADES

Misma petición en Fetch vs Axios

// Fetch
const res = await fetch(url, { method: 'POST', headers: { 'Content-Type': 'application/json' }, body: JSON.stringify(datos) });
if (!res.ok) throw new Error(res.status);
const dataFetch = await res.json();

// Axios
const { data: dataAxios } = await axios.post(url, datos);
Elemento / APIDescripción
InstalaciónFetch: Nativo (0 KB) | Axios: CDN o npm i axios
Cuerpo JSONFetch: JSON.stringify() | Axios: Automático
Lectura JSONFetch: await res.json() | Axios: res.data
Errores 404/500Fetch: Chequear res.ok | Axios: Va directo a catch
DIAPOSITIVA 4 · BUENAS PRÁCTICAS

Consejos y Errores Comunes

✅ Elige según el proyecto: Para scripts pequeños sin dependencias usa fetch(); para apps medianas/grandes con interceptores y timeout usa Axios.
⚠️ No olvides validar res.ok en Fetch: Es el error más común al pasar de Axios a Fetch.

DOS CLIENTES, UN MISMO OBJETIVO

¿Qué cambia entre Fetch y Axios?

1

Fetch

Es una API nativa del navegador. Convierte la respuesta con response.json() y no rechaza automáticamente los errores HTTP.

2

Axios

Es una biblioteca externa. Interpreta JSON automáticamente y rechaza la promesa cuando recibe un estado HTTP de error.

3

La petición

Ambos envían el mismo POST con los mismos datos. Cambia el cliente, no el resultado que buscamos.
