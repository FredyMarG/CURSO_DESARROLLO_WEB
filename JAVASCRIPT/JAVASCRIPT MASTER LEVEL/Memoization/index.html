Fundamentos

1. ¿Qué es la Memoización (*Memoization*)?

Es un patrón de diseño que intercambia un poco de memoria RAM a cambio de una mejora masiva en velocidad de CPU.

🐢

Cache Miss (Fallo de Caché)

Es la primera vez que la función recibe esos argumentos exactos. Ejecuta el cálculo completo, guarda el resultado en el diccionario y lo retorna.

⚡

Cache Hit (Acierto de Caché)

Los argumentos ya existen en el diccionario. Se omite todo el cálculo pesado y se devuelve la copia guardada en ~0.00 ms.

Requisito Indispensable

2. Funciones Puras e Idempotencia

Para memoizar de forma segura, una función debe ser determinista y carecer de efectos secundarios.

✅ Función Pura (Memoizable)

Mismas entradas = Misma salida

const calcularArea = (r) => Math.PI * r * r;
// Siempre retorna lo mismo para r = 5
❌ Función Impura (NO Memoizar)

Depende de tiempo, azar o estado externo

const horaActual = () => Date.now();
const azar = (n) => Math.random() * n;
Implementación Base

3. Anatomía Interna: Closures + `Map`

El Closure protege la caché privada entre llamadas, y Map ofrece búsqueda rápida con cualquier tipo de clave.

Patrón Clásico de 1 Argumento memoize.js 
const memoizarSimple = (fn) => {
    const cache = new Map(); // Privado gracias al Closure

    return (arg) => {
        if (cache.has(arg)) return cache.get(arg); // ⚡ Cache Hit
        const resultado = fn(arg); // 🐢 Cache Miss
        cache.set(arg, resultado);
        return resultado;
    };
};
Generalización

4. Memoización con Múltiples Argumentos (`...args`)

Serializamos el arreglo de parámetros con JSON.stringify(args) para obtener una clave única por combinación y tipo.

Soporte Universal de Parámetros multi-args.js 
const memoize = (fn) => {
    const cache = new Map();
    return (...args) => {
        const clave = JSON.stringify(args);
        if (cache.has(clave)) return cache.get(clave);
        const res = fn(...args);
        cache.set(clave, res);
        return res;
    };
};
Impacto en Rendimiento

5. El Caso Clásico: Fibonacci Recursivo

Evita recalcular el mismo subárbol millones de veces guardando cada término intermedio en la caché.

🐢 Sin Memoización: O(2ⁿ)

Crecimiento Exponencial

Para fibonacci(40) realiza más de 330 millones de llamadas repetidas.

const fib = n => n <= 1 ? n : fib(n-1) + fib(n-2);
⚡ Con Memoización: O(n)

Crecimiento Lineal Instantáneo

Para fibonacci(40) realiza exactamente 41 pasos en < 0.1 ms.

const fib = memoize(n => n <= 1 ? n : fib(n-1) + fib(n-2));
Gestión de Memoria

6. Límite de Caché (LRU) y `WeakMap`

Protege tu aplicación de fugas de memoria limitando el tamaño del Map o usando referencias débiles.

📏

Evicción con `maxSize`

Map conserva el orden de inserción; si excede el límite, borramos la clave más antigua:

if (cache.size >= maxSize) {
  const oldest = cache.keys().next().value;
  cache.delete(oldest);
}
🗑️

`WeakMap` para Objetos

Si la clave es un objeto grande o nodo DOM, WeakMap permite al Garbage Collector liberar su memoria automáticamente.

const cache = new WeakMap();
if (cache.has(obj)) return cache.get(obj);

Código de Producción

9. Proyecto Integrador: `crearMemoizer(fn, options)`

Implementación completa con soporte multi-argumento, límite máximo de caché (maxSize) y métricas.

Memoizer Profesional memoizer.js 
const crearMemoizer = (fn, { maxSize = 100 } = {}) => {
    const cache = new Map();
    const stats = { hits: 0, misses: 0 };
    const memoized = (...args) => {
        const key = JSON.stringify(args);
        if (cache.has(key)) { stats.hits++; return cache.get(key); }
        stats.misses++;
        const res = fn(...args);
        if (cache.size >= maxSize) cache.delete(cache.keys().next().value);
        cache.set(key, res);
        return res;
    };
    memoized.getStats = () => ({ ...stats, size: cache.size });
    return memoized;
};
