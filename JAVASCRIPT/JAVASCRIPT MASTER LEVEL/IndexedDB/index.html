Conceptos Fundamentales

1. Anatomía y Arquitectura de IndexedDB

IndexedDB no es una base de datos relacional con tablas y filas SQL, sino un almacén orientado a objetos (NoSQL).

📁

1. Base de Datos (IDBDatabase)

El contenedor global identificado por un nombre único y un número entero de versión (ej. "BD", 1). Un dominio web puede tener múltiples bases de datos.

🗄️

2. Almacén de Objetos (Object Store)

Equivalente a una "tabla" en SQL o una "colección" en MongoDB. Almacena registros como objetos nativos de JavaScript sin serializar a texto plano.

🔑

3. Clave Primaria (Primary Key)

Puede ser una propiedad interna del objeto mediante keyPath: "id" o un generador numérico automático mediante autoIncrement: true.

⚡

4. Índices (IDBIndex)

Estructuras secundarias que permiten realizar búsquedas rápidas por propiedades distintas a la clave primaria (ej. buscar usuarios por su email o rol).

Ciclo de Vida

2. Conexión y el Evento upgradeneeded

La conexión es asíncrona y se basa en eventos. La regla de oro: los almacenes sólo pueden crearse dentro de upgradeneeded. 

// 1. Solicitamos abrir la base de datos indicando nombre y versión entera
const IDBRequest = indexedDB.open("BD", 1);

// 2. Se dispara ÚNICAMENTE si la base es nueva o se incrementa el número de versión
IDBRequest.addEventListener("upgradeneeded", () => {
    const db = IDBRequest.result;
    
    // Creamos el almacén "nombres" con autoIncrement: true
    db.createObjectStore("nombres", {
        autoIncrement: true
    });
});

// 3. Se dispara cuando la base de datos está abierta y lista para operar
IDBRequest.addEventListener("success", () => console.log("Todo ok"));

// 4. Se dispara si ocurre un error de permisos o cuota
IDBRequest.addEventListener("error", (err) => console.log("Error", err));
Seguridad e Integridad

3. Transacciones: readonly vs readwrite

En IndexedDB ninguna operación de lectura o escritura ocurre de forma aislada: siempre debe ejecutarse dentro de una transacción.

👁️

Modo "readonly" (Solo Lectura)

Permite que el navegador ejecute múltiples transacciones en paralelo concurrentemente. Debe usarse siempre que se realicen consultas con .get(), .getAll() o cursores.

const tx = db.transaction("nombres", "readonly");
✍️

Modo "readwrite" (Lectura y Escritura)

Bloquea el almacén de forma exclusiva para garantizar consistencia. Permite añadir, modificar y borrar registros. Si una operación falla, todo se revierte (rollback automático).

const tx = db.transaction("nombres", "readwrite");
Manipulación de Datos

4. Métodos CRUD Fundamentales

Los cuatro métodos esenciales del IDBObjectStore para insertar, leer, actualizar y borrar datos.

CREATE

.add(objeto, key?)

Inserta un nuevo registro. Falla con ConstraintError si ya existe un registro con la misma clave primaria.

READ

.get(key) / .getAll()

Recupera un objeto por su clave primaria o un arreglo con todos los registros guardados en el almacén de forma asíncrona.

UPDATE

.put(objeto, key?)

Inserta el registro o lo sobrescribe si la clave primaria ya existe (comportamiento Upsert).

DELETE

.delete(key) / .clear()

Elimina un registro específico mediante su clave o borra todos los registros del almacén de una sola vez.

Iteración de Grandes Colecciones

5. Recorrido de Registros con Cursores

A diferencia de .getAll() que carga todo el contenido en memoria de golpe, openCursor() itera en streaming registro a registro. 

const leerObjetos = () => {
    const db = IDBRequest.result;
    const transaction = db.transaction("nombres", "readonly");
    const objectStore = transaction.objectStore("nombres");
    
    // Abrimos el cursor para recorrer el almacén
    const cursor = objectStore.openCursor();
    
    cursor.addEventListener("success", () => {
        if (cursor.result) {
            // cursor.result.value contiene el objeto actual
            console.log(cursor.result.value);
            // Avanzamos al siguiente elemento
            cursor.result.continue();
        } else {
            console.log("Todos los datos fueron leidos");
        }
    });
};

2

Arquitectura Moderna

8. Modernización con Promesas y async/await

La API nativa de IndexedDB se diseñó con eventos clásicos. Envolverla en Promise permite escribir código moderno y lineal. 

// Envolvemos la solicitud en una Promesa nativa
const obtenerTodosLosLibros = (db) => {
    return new Promise((resolve, reject) => {
        const tx = db.transaction(["libros"], "readonly");
        const store = tx.objectStore("libros");
        const req = store.getAll();
        
        req.onsuccess = () => resolve(req.result);
        req.onerror = () => reject(req.error);
    });
};

// Consumo limpio y moderno con async/await
const catalogo = await obtenerTodosLosLibros(db);
console.log(catalogo);

11. createIndex(), openCursor() y Hoja de Trucos

Optimiza búsquedas por campos secundarios y recorre grandes almacenes de objetos registro a registro.

🔍

Índices Secundarios (createIndex)

store.createIndex('por_email', 'email', { unique: true });
const req = store.index('por_email').get('a@b.com');

Permite consultar por propiedades distintas a la keyPath principal.

⏭️

Cursores (openCursor)

store.openCursor().onsuccess = (e) => {
  const cursor = e.target.result;
  if (cursor) { cursor.continue(); }
};

Itera registros de forma eficiente sin cargar miles de objetos en RAM.
