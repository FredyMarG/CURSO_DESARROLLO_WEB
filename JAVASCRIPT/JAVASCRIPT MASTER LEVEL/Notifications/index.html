Fundamentos

1. ¿Qué es la Notifications API y qué requisitos tiene?

Permite comunicar eventos importantes al usuario fuera de la ventana del navegador, bajo estrictas normas de privacidad.

💻

Más allá del `alert()` tradicional

A diferencia de un cuadro de diálogo bloqueante o un toast interno HTML, las notificaciones nativas:

  • Son visibles aunque el usuario haya minimizado el navegador.
  • No bloquean el hilo principal de JavaScript.
  • Integran título, cuerpo, icono, imagen y silencio opcional.
🔒

Contexto Seguro Obligatorio

Por seguridad y privacidad, la API solo funciona en entornos confiables:

// Comprobación previa obligatoria
if (!("Notification" in window)) {
  console.log("Navegador sin soporte");
}

Requiere protocolo HTTPS en producción o localhost durante desarrollo.

Control de Acceso

2. Verificación de Estado: `Notification.permission`

Antes de mostrar o pedir permiso, consulta siempre esta propiedad estática de solo lectura.

⏳

"default"

Notification.permission === "default"

El usuario aún no ha tomado una decisión. El navegador bloquea alertas hasta que se solicite permiso explícitamente.

✅

"granted"

Notification.permission === "granted"

El usuario autorizó las notificaciones para este dominio. Ya puedes instanciar new Notification().

🚫

"denied"

Notification.permission === "denied"

El usuario bloqueó el sitio. No se puede volver a mostrar el cuadro de solicitud por código; debe cambiarlo manualmente.

Promesas & UX

3. Solicitud de Autorización: `Notification.requestPermission()`

Despliega el cuadro de diálogo nativo del navegador y devuelve una Promesa con la decisión final del usuario.

Uso Moderno con async / await permisos.js 
const pedirPermiso = async () => {
    // La promesa se resuelve con "granted", "denied" o "default"
    const resultado = await Notification.requestPermission();

    if (resultado === "granted") {
        console.log("✅ ¡Permiso concedido por el usuario!");
    } else {
        console.log("❌ El usuario rechazó o cerró la solicitud.");
    }
};
⚠️ Regla de oro del gesto del usuario: Llama siempre a requestPermission() dentro de un evento iniciado por el usuario (como el click de un botón). Si lo ejecutas automáticamente al cargar la página, los navegadores modernos lo bloquearán.
Constructor & Configuración

4. Creación y Envío: `new Notification(titulo, options)`

Cuando el permiso es "granted", instancia el constructor pasando el título y un objeto opcional de propiedades.

⚙️

Opciones Principales

body Texto descriptivo secundario debajo del título.
icon URL de la imagen o logotipo de la alerta.
tag Identificador único para reemplazar alertas previas con el mismo tag.
silent Booleano: true silencia el sonido o vibración del sistema.
🚀

Ejemplo de Envío

if (Notification.permission === "granted") {
  const noti = new Notification("¡Proceso Listo!", {
    body: "Tu reporte ya está disponible.",
    icon: "icono.png",
    tag: "reporte-mensual"
  });
}
Interacción Directa

5. Eventos de la Instancia de Notificación

Cada instancia de Notification emite eventos para reaccionar cuando el usuario interactúa con ella.

📡

Eventos Disponibles

  • "click": El usuario hizo clic sobre la tarjeta de notificación.
  • "close": El usuario cerró la alerta o expiró automáticamente.
  • "show": Instante exacto en que la notificación aparece en pantalla.
  • "error": Ocurrió un fallo al intentar mostrar la notificación.
🪟

Enfocar Ventana al Clic

Lleva al usuario de regreso a tu pestaña y cierra el aviso:

noti.addEventListener("click", () => {
  window.focus(); // Trae el navegador al frente
  noti.close();   // Cierra la notificación
});

6. Analogías del Mundo Real

Dos metáforas cotidianas para recordar cómo operan los permisos y la agrupación por etiquetas.

🏢

1. El Portero de un Edificio (`requestPermission`)

Antes de dejar subir a un repartidor con tu paquete (new Notification), el portero llama por el citófono para pedirte permiso (requestPermission()). Si dices que sí ("granted"), los siguientes paquetes suben directo. Si le dices que no moleste ("denied"), rechazará entregas futuras.

📌

2. El Tablero de Avisos con Etiquetas (`tag`)

Usar la propiedad tag es como tener un espacio reservado en la pizarra con el título "Estado de descarga": en lugar de pegar 10 notas adhesivas distintas por cada avance, reemplazas la misma nota actualizando su contenido.

7. Buenas Prácticas y Errores Comunes

Diseña alertas respetuosas que aporten valor sin molestar al usuario ni provocar bloqueos del navegador.

✅ Buena Práctica 1

Combinar con visibilitychange

❌ Lanzar alerta externa si el usuario ya mira la web
✔️ Usar new Notification() solo si document.hidden === true

Si el usuario ya está viendo la pestaña, muéstrale un aviso interno; reserva las alertas del SO para segundo plano.

✅ Buena Práctica 2

Agrupar Alertas con tag

❌ Emitir 15 notificaciones sin tag en un chat activo
✔️ Usar tag: "chat-sala-1" para reemplazar

Evita saturar el centro de notificaciones del usuario y reduce el riesgo de que revoque el permiso.

❌ Error Común 1

Pedir Permiso al Cargar la Página

❌ Notification.requestPermission() en DOMContentLoaded
✔️ Solicitarlo dentro de btn.addEventListener("click")

Los navegadores bloquean las solicitudes automáticas sin gesto explícito del usuario.

❌ Error Común 2

Ignorar el Estado "denied"

❌ Intentar abrir el diálogo cuando ya está en "denied"
✔️ Informar cómo habilitarlo desde el candado de la URL

Cuando un sitio está denegado, JavaScript no puede volver a mostrar el diálogo nativo.

9. Proyecto Integrador: Sistema de Alertas Inteligente

Patrón completo que gestiona el botón de permisos, actualiza la interfaz y emite alertas interactivas con click.

Gestión Completa de Permisos y Eventos alertas.js 
const mostrarNotificacion = (titulo, mensaje) => {
    if (Notification.permission !== "granted") return;

    const alerta = new Notification(titulo, {
        body: mensaje,
        tag: "alerta-sistema"
    });

    alerta.addEventListener("click", () => {
        window.focus();
        alerta.close();
    });
};

10. Resumen Técnico del Módulo

Conceptos esenciales para implementar notificaciones nativas seguras y efectivas en producción.

🔍

Notification.permission

🔔

new Notification()

Crea alertas nativas del SO configurando body, icon, tag y silent.

11. Service Worker Notifications y Cheatsheet

Emite notificaciones persistentes con botones de acción en PWAs y repasa la API.

📲

showNotification() en PWA

const reg = await navigator.serviceWorker.ready;
reg.showNotification('Pedido #402', {
  actions: [{ action: 'ver', title: 'Ver' }]
});

Permite mostrar botones interactivos y alertas incluso con la pestaña cerrada.

👀

Sinergia con visibilitychange

if (document.hidden && Notification.permission === 'granted') {
  new Notification('Nuevo mensaje');
}

Muestra alerta externa solo si el usuario no está mirando la pestaña.

📋
