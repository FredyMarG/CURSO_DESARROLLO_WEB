01 / FUNDAMENTOS

¿Qué es una Cookie y por qué existe?

El protocolo HTTP es sin estado (stateless): cada petición es independiente y el servidor olvida al usuario inmediatamente después de responder. Las cookies son pequeños archivos de texto (~4 KB) que el navegador guarda y reenvía automáticamente en cada petición al mismo dominio.

🔄 Flujo Cliente ↔ Servidor

  • 1. Respuesta inicial: el servidor envía la cabecera Set-Cookie: tema=oscuro (o JS escribe en document.cookie).
  • 2. Almacenamiento local: el navegador guarda la cookie asociada al dominio y ruta.
  • 3. Peticiones futuras: en cada nuevo request HTTP al dominio, el navegador adjunta automáticamente Cookie: tema=oscuro.

🎯 Usos principales

  • Sesiones e inicio de sesión: identificar usuarios autenticados y carritos de compra.
  • Preferencias UX: recordar tema visual, idioma o región.
  • Analítica y seguimiento: medir visitas recurrentes o campañas.
02 / TAXONOMÍA

Tipos y Clasificación de Cookies

⏱️ Por Duración

  • De Sesión: sin max-age ni expires; mueren al cerrar el navegador.
  • Persistentes: permanecen en disco hasta la fecha o segundos configurados.

🌍 Por Procedencia

  • First-Party (Propias): creadas por el dominio que visitas directamente.
  • Third-Party (Terceros): creadas por scripts externos (embeds, ads, analítica).

📋 Por Finalidad

  • Técnicas: esenciales para login y seguridad.
  • Preferencias: idioma, tema, layout.
  • Analítica / Ads: métricas y personalización.
03 / ESCRITURA

Crear y Modificar Cookies con document.cookie

Aunque document.cookie parece una propiedad de texto normal, internamente funciona como un setter inteligente: asignar una nueva cadena añade o actualiza esa cookie sin borrar las demás.

crear_modificar.js
// 1. Cookie básica de sesión (muere al cerrar el navegador)
document.cookie = "usuario=JuanPerez";

// 2. Cookie persistente con atributos recomendados (1 día = 86400s)
document.cookie = "tema=oscuro; max-age=86400; path=/; Secure; SameSite=Lax";

// 3. Modificar: se sobrescribe usando el MISMO nombre, path y domain
document.cookie = "tema=claro; max-age=86400; path=/; Secure; SameSite=Lax";

⚙️ Atributos clave

  • max-age=SEGUNDOS: duración relativa (tiene prioridad sobre expires).
  • expires=FECHA_UTC: fecha exacta en formato UTC (new Date(...).toUTCString()).
  • path=/: hace accesible la cookie en todo el sitio (por defecto solo en la ruta actual).
  • Secure y SameSite=Strict | Lax | None: cifrado HTTPS y protección contra CSRF.
04 / CODIFICACIÓN

encodeURIComponent() y decodeURIComponent()

El formato de cookies usa ;, = y espacios como separadores. Si guardas texto con esos caracteres sin codificar, el valor se cortará o romperá la cookie.

❌ Sin codificar (Se rompe)

// El ';' corta el valor después de "Admin"
document.cookie = "perfil=Admin; Nivel=5";
// El navegador guarda solo "perfil=Admin"!

✅ Codificado (100% Seguro)

const val = encodeURIComponent("María; Admin=1");
document.cookie = `perfil=${val}; path=/`;

// Al leer:
decodeURIComponent(val); // "María; Admin=1"
05 / LECTURA Y BORRADO

Leer una Cookie Específica y Eliminarla

Al leer document.cookie recibes un único string con todas las cookies separadas por "; ". Para borrar una cookie, se sobrescribe con max-age=0 y el mismo path.

crud_cookies.js
// Leer una cookie por nombre de forma segura
function obtenerCookie(nombre) {
    const clave = encodeURIComponent(nombre) + "=";
    const lista = document.cookie.split("; ");
    for (const item of lista) {
        if (item.startsWith(clave)) {
            return decodeURIComponent(item.slice(clave.length));
        }
    }
    return null;
}

// Eliminar una cookie (mismo nombre y mismo path original)
function eliminarCookie(nombre, path = "/") {
    document.cookie = `${encodeURIComponent(nombre)}=; max-age=0; path=${path}`;
}

07 / PRODUCCIÓN

Errores Frecuentes y Buenas Prácticas

⚠️ Errores comunes

  • Olvidar path=/ al modificar o eliminar y generar cookies duplicadas.
  • Guardar objetos grandes (>4 KB) en cookies en vez de localStorage o IndexedDB.
  • Almacenar contraseñas o JWT sensibles en cookies accesibles por JS sin HttpOnly.

✅ Buenas prácticas

  • Codifica siempre claves y valores con encodeURIComponent().
  • Usa SameSite=Lax o Strict y Secure en HTTPS.
  • Mantén las cookies ligeras para no ralentizar cada petición HTTP.
