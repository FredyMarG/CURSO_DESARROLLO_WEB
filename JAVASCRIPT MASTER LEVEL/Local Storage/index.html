Fundamento 01

¿Qué es el Almacenamiento Web (Web Storage)?

Es una API nativa de los navegadores modernos que permite guardar datos localmente en el dispositivo del usuario bajo un formato de clave-valor (key-value):

Evolución frente a las Cookies

Cero Tráfico de Red Innecesario: A diferencia de las antiguas Cookies, los datos de Web Storage no se envían automáticamente al servidor en cada petición HTTP.

Alta Capacidad en Frontend: Ofrece entre 5MB y 10MB de espacio por origen (frente a los apenas 4KB de una Cookie) con una API de JavaScript limpia e intuitiva.

💡 Regla Fundamental: Tanto las claves como los valores en Web Storage se almacenan exclusivamente como cadenas de texto (strings).

Antiguas Cookies HTTP

  • Capacidad diminuta de apenas 4 KB.
  • Viajan al servidor en cada petición HTTP.
  • Sintaxis de lectura y escritura manual compleja.

Web Storage Moderno

  • Capacidad amplia de 5 MB a 10 MB.
  • 100% local en el cliente (cero peso en red).
  • Métodos nativos directos: setItem / getItem.
primer_contacto_localstorage.js 
"use strict";
// 1. Guardamos el par clave-valor en el navegador:
localStorage.setItem("nombre", "Fredy");
console.log(localStorage);

// 2. Recuperamos el valor usando su clave:
let nombre = localStorage.getItem("nombre");
console.log(nombre); // Imprime: "Fredy"

Fundamento 02

LocalStorage vs. SessionStorage y Anatomía de los 4 Métodos

Ambos mecanismos comparten exactamente la misma API de 4 métodos, pero difieren en su persistencia y ámbito:

Anatomía de la API

Los 4 Métodos Fundamentales

Idénticos en localStorage y sessionStorage
  • 1. setItem(clave, valor): Inserta o actualiza un par clave-valor.
  • 2. getItem(clave): Lee el valor; si no existe devuelve null.
  • 3. removeItem(clave): Borra únicamente la clave especificada.
  • 4. clear(): Vacía todas las claves del origen actual.
🔍
Retorno ante Clave Inexistente: A diferencia de los objetos comunes (undefined), getItem() retorna estrictamente null.

Persistencia y Ámbito

¿Permanente o por Pestaña?

Elige según el caso de uso

LocalStorage 💾: Permanente (no expira al cerrar el navegador) y compartido entre todas las pestañas del mismo dominio.
SessionStorage ⏱️: Temporal (muere al cerrar la pestaña) y aislado exclusivamente en la pestaña actual.

Ejemplo Clave: Usa localStorage para el tema oscuro/idioma y sessionStorage para un formulario multipaso.

Arquitectura y Blindaje

Diagrama de Flujo de Decisión, Blindaje try...catch y Seguridad

Aprende el árbol de decisiones para elegir el almacenamiento correcto y cómo proteger tu aplicación frente a datos corruptos y vulnerabilidades:

5.1 Diagrama de Flujo de Decisión de Persistencia

¿Debe persistir al cerrar el navegador? ¿Es un Objeto o Array?

Paso 1: Si los datos deben sobrevivir al cierre del navegador, elige localStorage; si solo sirven para la pestaña actual, elige sessionStorage.
Paso 2: Si el valor es un Objeto o Array, aplícale JSON.stringify() antes de llamar a .setItem().

5.2 Envuelve siempre JSON.parse() en un bloque try...catch

Evita que un JSON corrupto rompa toda tu aplicación web

El usuario o una extensión puede alterar manualmente el contenido desde las DevTools del navegador. Si JSON.parse() encuentra texto inválido sin un bloque try...catch, lanzará un SyntaxError fatal que dejará la pantalla en blanco.

Haz clic para simular la recuperación segura cuando el almacenamiento está dañado...
5.3 Prohibido Guardar Información Confidencial

Cualquier script en la página puede leer localStorage.getItem()

Nunca guardes contraseñas, números de tarjetas de crédito ni datos médicos en Web Storage. Si tu sitio sufre una inyección de scripts (ataque XSS) o carga una librería maliciosa, el atacante podrá extraer todo el contenido de localStorage en una sola línea.

Estándares de la Industria

Buenas Prácticas y Errores Comunes con Web Storage

Evita los 4 tropiezos más frecuentes al trabajar con persistencia en el navegador:

❌ ERROR: "[object Object]"

Guardar Objetos sin JSON.stringify

Pasar un objeto o array directamente a setItem() ejecuta .toString() de forma implícita, destruyendo la información original.

localStorage.setItem("cfg", {a: 1}); // ❌ "[object Object]"
❌ ERROR: EL STRING "false" ES TRUTHY

Asumir que Regresa el Tipo Original

setItem("login", false) guarda el texto "false". En un condicional if (getItem("login")), cualquier string no vacío evalúa como true.

if (localStorage.getItem("login")) // ❌ Entra con "false"
✅ BUENA PRÁCTICA: LECTURA SEGURA

Usar try...catch y Validar null

Verifica siempre si getItem() devolvió null antes de usarlo y envuelve JSON.parse() en un bloque try...catch con valor por defecto.

return datos ? JSON.parse(datos) : []; // ✅
✅ BUENA PRÁCTICA: PRIVACIDAD Y CUOTA

Cero Datos Sensibles y Control de Peso

Usa Web Storage solo para preferencias de UI o estado público no sensible, respetando el límite de 5MB-10MB para evitar errores en dispositivos móviles.

localStorage.setItem("app_lang", "es"); // ✅ Seguro
Casos Reales de Producción

Persistencia de Arrays (Historial) y Sistema de Preferencia de Idioma

Observa cómo se implementan los patrones de almacenamiento más solicitados en aplicaciones reales:

1. Guardar y Recuperar Arrays (Historial)

Serializamos el arreglo con JSON.stringify() al guardar y retornamos un array vacío [] como respaldo si la clave aún no existe: 

const guardarHistorial = lista =>
  localStorage.setItem("busquedas", JSON.stringify(lista));

const obtenerHistorial = () => {
  const raw = localStorage.getItem("busquedas");
  return raw ? JSON.parse(raw) : [];
};

2. Sistema de Preferencia de Idioma (i18n)

Al iniciar la aplicación, verificamos si existe la clave "app_lang"; si es la primera visita, configuramos y guardamos "es" por defecto: 

const IDIOMA_KEY = "app_lang";
const inicializarIdioma = () => {
  const guardado = localStorage.getItem(IDIOMA_KEY);
  if (guardado) return guardado;
  localStorage.setItem(IDIOMA_KEY, "es");
  return "es";
};

Nivel 2 — Semi Senior

guardarHistorial y obtenerHistorial (Arrays)

Crea guardarHistorial(lista) para guardar un array en localStorage bajo la clave "busquedas", y obtenerHistorial() que retorne el array original (o [] si no existe). 

const guardarHistorial = (listaBusquedas) => {
    localStorage.setItem("busquedas", JSON.stringify(listaBusquedas));
};

const obtenerHistorial = () => {
    const datosRaw = localStorage.getItem("busquedas");
    if (!datosRaw) return [];
    try {
        return JSON.parse(datosRaw);
    } catch (error) {
        return [];
    }
};
Nivel 3 — Producción

Sistema de Preferencia de Idioma

Programa cambiarIdioma(nuevoIdioma) para guardar la preferencia en localStorage, e inicializarIdioma() que retorne el idioma guardado o configure y retorne "es" por defecto. 

const IDIOMA_KEY = "app_lang";

const cambiarIdioma = (nuevoIdioma) => {
    localStorage.setItem(IDIOMA_KEY, nuevoIdioma);
};

const inicializarIdioma = () => {
    const guardado = localStorage.getItem(IDIOMA_KEY);
    if (guardado) return guardado;
    localStorage.setItem(IDIOMA_KEY, "es");
    return "es";
};
