Fundamento 01

¿Qué es el Modo Estricto y por qué existe?

Durante años, JavaScript mantuvo decisiones de diseño ambiguas para no romper webs antiguas. ES5 introdujo "use strict" como una directiva para habilitar una variante segura y robusta.

Definición Formal

"use strict" es una expresión literal introducida en ECMAScript 5 (ES5) que indica al motor de ejecución que interprete el código bajo un conjunto de reglas mucho más estrictas.

💡 Compatibilidad garantizada: Los navegadores antiguos que no lo entendían simplemente lo leían como una cadena de texto inofensiva y continuaban sin fallar.

Sloppy Mode (Modo Normal)

  • Tolera errores graves sin avisar.
  • Crea variables globales por error tipográfico.
  • Obliga al motor a hacer comprobaciones lentas.

Strict Mode ("use strict")

  • Lanza excepciones inmediatas y descriptivas.
  • Prohíbe ensuciar el objeto global window.
  • Permite al compilador optimizar el código al máximo.
comparativa_directiva.js 
// 1. Activación con la directiva literal:
"use strict";

// 2. Intento de asignar sin declarar con let/const:
try {
    usuarioSinDeclarar = "Elena";
} catch (error) {
    console.error(error.name + ": " + error.message);
    // Resultado: ReferenceError: usuarioSinDeclarar is not defined
}

Rendimiento Interno V8

Optimización del Motor y Tiempos de Ejecución

El código ambiguo fuerza al compilador a realizar comprobaciones costosas. El Modo Estricto elimina 3 cuellos de botella críticos en la memoria RAM:

5.1 Aislamiento del Ámbito de eval()

Las variables creadas dentro de eval() no contaminan el exterior

En modo normal, eval("var secreta = 42;") inyecta la variable en tu función actual. En modo estricto, eval() crea un entorno de ámbito aislado, permitiendo al compilador optimizar las variables locales sin temor a modificaciones invisibles.

Haz clic para comprobar cómo eval() no escapa de su celda en Modo Estricto...
5.2 Desvinculación de arguments y Parámetros

Elimina la sincronización mágica costosa en memoria RAM

En modo descuidado, modificar el valor de un parámetro modificaba automáticamente arguments[0] y viceversa. Mantener esta sincronización en tiempo real consumía recursos del procesador. En "use strict", son totalmente independientes.

Haz clic para evaluar la independencia de parámetros...
5.3 Eliminación Total de la Sentencia 'with'

Búsqueda estática y directa de identificadores en memoria

La sentencia with (objeto) { ... } hacía imposible saber en tiempo de compilación si una variable pertenecía al objeto o al ámbito local. El Modo Estricto prohíbe 'with', arrojando un SyntaxError y permitiendo que V8 ejecute optimizaciones inline rápidas.

Guardián de Calidad

Eliminación de la "Mala Sintaxis" y Descuidos Graves

JavaScript corrige 4 malas prácticas históricas que originaban los bugs más difíciles de depurar en producción:

❌ SLOppy: CONTAMINA WINDOW

Variables Globales por Accidente

Olvidar let/const o cometer una errata tipográfica crea una variable global en window. En Strict Mode lanza ReferenceError.

totalPrecio = 100; // ❌ ReferenceError
❌ SLOPPY: SOBRESCRIBE PARÁMETRO

Parámetros Duplicados en Funciones

En modo normal, function suma(a, b, a) sobrescribía silenciosamente el primer parámetro. En Strict Mode lanza SyntaxError.

function(x, y, x) {} // ❌ SyntaxError
❌ SLOPPY: 010 ES IGUAL A 8

Literales Octales con Cero Inicial

Escribir 0123 hacía que JS lo interpretara en base 8, generando errores matemáticos. En Strict Mode exige la sintaxis explícita 0o123.

const cp = 0123; // ❌ SyntaxError
✅ STRICT: THIS ES UNDEFINED

'this' Seguro en Funciones Sueltas

Llamar una función simple sin objeto contexto en modo normal asignaba this = window. En Strict Mode, this es limpiamente undefined.

function f() { console.log(this); } // undefined

Resumen Maestro y Retos de Evaluación

Nivel 1 — Junior

Erratas Tipográficas Detectadas

Declara una variable con let y en la siguiente línea asígnale un valor cometiendo una errata tipográfica a propósito en modo estricto. 

"use strict";
let contadorVisitas = 10;
// Provocamos el ReferenceError:
try {
    contadoorVisitas = 11;
} catch (e) {
    console.error("Atrapado:", e.message);
}
Nivel 2 — Semi Senior

Captura de TypeError en Object.freeze()

Crea un objeto configuracionServidor = { puerto: 8080 }, congélalo con Object.freeze() e intenta modificarlo dentro de un bloque try/catch. 

"use strict";
const configuracionServidor = { puerto: 8080 };
Object.freeze(configuracionServidor);

try {
    configuracionServidor.puerto = 3000; // TypeError!
} catch (err) {
    console.error("Seguridad activada:", err.message);
}
Nivel 3 — Master
