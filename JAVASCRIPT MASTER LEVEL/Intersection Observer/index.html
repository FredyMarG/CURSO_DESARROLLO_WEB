Intersection Observer API

Detecta de forma asíncrona y sin bloquear el hilo principal cuándo un elemento entra o sale del viewport, optimizando el rendimiento web para crear carga diferida, animaciones al scroll y reproducción inteligente.

Arquitectura de Rendimiento

1. ¿Por qué `IntersectionObserver` supera al evento `scroll`?

Compara cómo el navegador resuelve la detección de visibilidad entre el enfoque síncrono clásico y la API asíncrona moderna.

⚠️ Enfoque Antiguo: evento scroll

Cálculos Costosos en el Hilo Principal

Cada pixel desplazado invoca funciones pesadas que obligan al navegador a recalcular el diseño completo (Layout Reflow).

  • ❌ Se dispara decenas de veces por segundo.
  • ❌ getBoundingClientRect() fuerza cálculos sincrónicos de geometría.
  • ❌ Provoca tirones visuales (jank) y alto consumo de batería en móviles.
window.addEventListener("scroll", () => {
  const rect = el.getBoundingClientRect(); // 💥 Reflow continuo
});
✅ Moderno: IntersectionObserver

Vigilancia Asíncrona en el Motor del Navegador

Delega el seguimiento geométrico al navegador fuera del hilo principal y ejecuta el callback solo al cruzar el umbral.

  • ✔️ 0% de carga de CPU mientras no se crucen los límites configurados.
  • ✔️ Entrega métricas ya calculadas sin forzar reflow.
  • ✔️ Soporta múltiples objetivos con una sola instancia ligera.
const io = new IntersectionObserver(callback, options);
io.observe(elemento); // 🚀 Vigilancia asíncrona óptima
Sintaxis Fundamental

2. El Constructor `new IntersectionObserver()` y `.observe()`

Para comenzar a vigilar elementos del DOM, primero instanciamos el observador con sus reglas y luego le asignamos uno o más objetivos.

Estructura Base de Creación observador.js 
// 1. Seleccionamos el elemento del DOM que deseamos vigilar
const caja = document.getElementById("caja-objetivo");

// 2. Definimos la función callback que responderá a los cambios
const callback = (entries, observer) => {
    entries.forEach(entry => {
        console.log("Elemento:", entry.target, "Visible:", entry.isIntersecting);
    });
};

// 3. Instanciamos el observador (options es opcional)
const observador = new IntersectionObserver(callback, options);

// 4. Iniciamos la vigilancia sobre el elemento objetivo
observador.observe(caja);
💡 Evaluación inicial automática: Al llamar a observador.observe(caja), el navegador ejecuta el callback una vez de forma inmediata para reportar el estado actual del elemento, incluso antes de que el usuario mueva el scroll.
Anatomía de la Respuesta

3. Parámetros del `callback`: `entries` e `isIntersecting`

Cada vez que un elemento observado cruza un umbral, el callback recibe un arreglo de objetos IntersectionObserverEntry.

📦

Propiedades de cada `entry`

.isIntersecting Booleano (true / false). Confirma si el elemento está entrando o saliendo de la zona visible.
.intersectionRatio Número entre 0.0 y 1.0 indicando la fracción exacta visible del elemento.
.target Referencia directa al nodo HTML que originó el evento de intersección.
.boundingClientRect Coordenadas calculadas sin provocar reflow en el hilo principal.
🎯

Validación Obligatoria

El callback se dispara tanto al entrar como al salir de pantalla. Usa siempre entry.isIntersecting:

const callback = (entries) => {
  entries.forEach(entry => {
    if (entry.isIntersecting) {
      entry.target.classList.add("visible");
    } else {
      entry.target.classList.remove("visible");
    }
  });
};
Control Milimétrico

4. Configuración de `options`: `root`, `rootMargin` y `threshold`

El segundo argumento del constructor personaliza el marco de visión, la zona de anticipación y el porcentaje necesario para disparar la detección.

🖼️

1. root

root: null (o Elemento)

Define el contenedor padre que actúa como ventana de vigilancia. null utiliza el viewport principal del navegador; también acepta un div con overflow: auto.

📏

2. rootMargin

rootMargin: "0px 0px 200px 0px"

Funciona igual que margin en CSS. Valores positivos agrandan el área para precargar recursos antes de que entren; valores negativos la encogen.

📊

3. threshold (Umbral)

threshold: [0, 0.5, 1.0]

Porcentaje visible requerido (0.0 a 1.0). Un valor de 0 dispara apenas asoma 1px; un arreglo dispara múltiples veces al cruzar cada hito.

const options = { root: null, rootMargin: "150px", threshold: 0.25 };
Gestión de Memoria

5. Métodos de Control: `observe()`, `unobserve()` y `disconnect()`

Controla con exactitud cuándo iniciar, pausar o destruir la vigilancia para evitar fugas de memoria y ejecuciones redundantes.

👁️

observer.observe(target)

observador.observe(tarjeta);

Añade un elemento del DOM a la lista de vigilancia activa. Puedes llamar este método múltiples veces sobre distintos nodos con una misma instancia.

🧹

observer.unobserve(target)

observer.unobserve(entry.target);

Detiene la vigilancia sobre un elemento específico. Imprescindible en Lazy Loading o animaciones de una sola ejecución tras completarse.

🔌

observer.disconnect()

observador.disconnect();

Detiene de golpe la observación de todos los elementos asociados a la instancia. Ideal al desmontar componentes en SPAs.

6. Analogías del Mundo Real

Comprende cómo trabajan juntos IntersectionObserver, root, rootMargin y threshold.

🚪

1. El Sensor de una Puerta Automática

IntersectionObserver es el sensor infrarrojo encima de la puerta de un supermercado. No pregunta cada milisegundo "¿hay alguien?" (como scroll); descansa hasta que alguien cruza su haz de luz. El rootMargin positivo es la distancia previa que detecta el sensor para abrir la puerta antes de que choques con el vidrio.

🖼️

2. El Marco de una Fotografía

El root es el marco físico de madera. La propiedad isIntersecting se vuelve true en el instante en que deslizas una fotografía detrás del marco y parte de ella asoma por el cristal. Si configuras threshold: 1.0, la foto solo cuenta como "colocada" cuando encaja al 100% dentro del marco.

7. Buenas Prácticas y Errores Comunes

Sigue estas recomendaciones para escribir observadores eficientes, libres de fugas y sin comportamientos inesperados.

✅ Buena Práctica 1

Reutiliza una Sola Instancia

❌ Crear 50 new IntersectionObserver() en un forEach
✔️ 1 instancia + cards.forEach(c => io.observe(c))

Si múltiples tarjetas comparten las mismas reglas, un único observador puede vigilarlas todas a la vez.

✅ Buena Práctica 2

Usa unobserve() en Acciones Únicas

❌ Seguir vigilando imágenes que ya cargaron
✔️ observer.unobserve(entry.target) al terminar

Libera memoria y evita reevaluar elementos cuyo trabajo ya finalizó (Lazy Load o animaciones iniciales).

❌ Error Común 1

Olvidar Validar entry.isIntersecting

❌ Cargar imagen sin comprobar if (!entry.isIntersecting)
✔️ if (!entry.isIntersecting) return;

El callback se dispara al entrar Y al salir. Sin esta comprobación, tu lógica se ejecutará dos veces.

❌ Error Común 2

Usar threshold: 1 en Elementos Gigantes

❌ Elemento de 1200px en pantalla de 800px con threshold: 1
✔️ Usar threshold: 0.1 o 0.25 para secciones altas

Si el elemento no cabe entero en la pantalla, nunca alcanzará el 100% visible y el callback jamás se disparará.

Caso de Uso Real

9. Proyecto Práctico: Lazy Loading de Imágenes

Implementación profesional donde las imágenes guardan su URL real en data-src y solo se descargan cuando el usuario está a 150px de verlas.

HTML Declarativo

Atributo `data-src`

Mantenemos src vacío o con un placeholder ligero para no saturar la red al cargar la página.

<div class="galeria">
  <img class="lazy-img" data-src="foto-hd-1.jpg" alt="Paisaje 1">
  <img class="lazy-img" data-src="foto-hd-2.jpg" alt="Paisaje 2">
  <img class="lazy-img" data-src="foto-hd-3.jpg" alt="Paisaje 3">
</div>
JavaScript Moderno

Precarga + Unobserve

Descargamos bajo demanda y desconectamos la vigilancia inmediatamente después.

const opciones = { rootMargin: "0px 0px 150px 0px", threshold: 0.1 };
const cargarImagen = (entries, observer) => {
  entries.forEach(entry => {
    if (!entry.isIntersecting) return;
    entry.target.src = entry.target.dataset.src;
    observer.unobserve(entry.target);
  });
};
const io = new IntersectionObserver(cargarImagen, opciones);
document.querySelectorAll(".lazy-img").forEach(img => io.observe(img));

11. Scroll Infinito, Control de Video y Cheatsheet

Aplica centinelas para carga infinita y pausa automática de multimedia fuera de pantalla.

♾️

Scroll Infinito con Centinela

const io = new IntersectionObserver(entries => {
  if (entries[0].isIntersecting) cargarMas();
}, { rootMargin: '200px' });

Observa un div vacío al final de la lista para precargar antes de llegar al fondo.

🎬

Auto-Pausa de Video

entries.forEach(e => e.isIntersecting ? e.target.play() : e.target.pause());

Ahorra ancho de banda y batería pausando videos cuando salen del viewport.

📋
