Media Queries Dinámicas:
window.matchMedia()

Aprende a sincronizar la lógica de JavaScript con tus reglas de diseño responsive, dominando la propiedad matches, el evento change y el objeto MediaQueryList sin saturar el procesador con eventos resize continuos.

⚡

Alto Rendimiento

Cero sobrecarga de CPU. Solo se notifica a JavaScript en el instante exacto en que se cruza el umbral de pantalla.

🎯

Evaluación Inicial

Lee el estado actual de cualquier regla CSS al instante con la propiedad booleana .matches.

🔄

Reactividad Nativa

Suscríbete a cambios del viewport, orientación o preferencias del sistema mediante addEventListener("change").

🌙

Preferencias del SO

Detecta el modo oscuro del sistema, preferencias de accesibilidad y dispositivos táctiles con sintaxis CSS.

Fundamentos de la API

1. ¿Qué es y cómo se compone `MediaQueryList`?

window.matchMedia() recibe una regla CSS y devuelve una instancia especializada de MediaQueryList.

🔍

Sintaxis Básica

Debes pasar siempre una regla de Media Query válida entre paréntesis obligatorios:

const mql = window.matchMedia("(max-width: 768px)");
console.log(mql); // Retorna MediaQueryList
  • Paréntesis requeridos: Si omites los paréntesis "max-width: 768px", el navegador fallará en silencio y matches siempre será false.
  • Sintaxis universal: Acepta cualquier condición soportada por CSS (resolución, aspect-ratio, colores, punteros).
📋

Propiedades & Métodos Clave

.matches Booleano (true / false) indicando si la regla se cumple en este instante.
.media Cadena serializada con la consulta CSS normalizada (ej: "(max-width: 768px)").
"change" Evento que se dispara únicamente al alternar entre cumplimiento y no cumplimiento.
.onchange Manejador de propiedad directa para asignar una función de retorno rápida.
Arquitectura de Código

2. El Patrón Profesional: Inicialización + Escucha

El evento change no se dispara al cargar la página. Por ello, el estándar de la industria exige evaluar el estado inicial de inmediato.

Patrón de Oro Recomendado script.js 
// 1. Instanciamos la consulta de medios
const mqEscritorio = window.matchMedia("(min-width: 1024px)");

// 2. Diseñamos la función reactiva que recibe el evento o el objeto MQL
const gestionarLayout = (evento) => {
    if (evento.matches) {
        console.log("🖥️ Pantalla grande: Mostrar barra lateral y montar mapa complejo.");
    } else {
        console.log("📱 Pantalla compacta: Ocultar barra lateral y activar menú móvil.");
    }
};

// 3. EVALUACIÓN INICIAL OBLIGATORIA: Ejecutamos al cargar la página
gestionarLayout(mqEscritorio);

// 4. ESCUCHA REACTIVA DINÁMICA: Escuchamos transiciones futuras
mqEscritorio.addEventListener("change", gestionarLayout);
💡 ¿Por qué pasar `mqEscritorio` en el paso 3? Tanto el objeto MediaQueryList inicial como el objeto MediaQueryListEvent que pasa el evento change exponen la misma propiedad .matches, permitiendo que la misma función atienda ambos momentos de forma limpia e isomórfica.
Optimización Web

3. Comparativa: `window.resize` vs `window.matchMedia()`

Por qué escuchar el evento resize para lógica responsive degrada el rendimiento y cómo matchMedia() lo soluciona nativamente.

⚠️ Tradicional: window.resize

Monitoreo Continuo & Costoso

Se dispara cientos de veces por segundo al redimensionar la ventana o rotar el móvil.

  • ❌ Consume ciclos de CPU innecesarios durante el arrastre.
  • ❌ Obliga a implementar debounce o throttle manual con temporizadores.
  • ❌ Provoca jank visual y pérdida de fotogramas (FPS) en navegadores móviles.
window.addEventListener("resize", () => {
  if (window.innerWidth <= 768) { /* ... */ }
}); // 💥 100+ ejecuciones continuas
✅ Moderno: window.matchMedia()

Monitoreo Puntual a Nivel de Motor

Se dispara una única vez exclusivamente en el instante exacto en que se cruza el umbral definido.

  • ✔️ 0% de sobrecarga de CPU mientras la ventana cambia dentro del mismo rango.
  • ✔️ No requiere temporizadores, debouncing ni librerías externas.
  • ✔️ Sincronizado a nivel nativo con el motor de renderizado CSS del navegador.
const mq = window.matchMedia("(max-width: 768px)");
mq.addEventListener("change", (e) => { /* ... */ });
// 🚀 1 sola ejecución al cruzar el umbral

5. Metáfora del Mundo Real: El Termostato Inteligente 🌡️

Comprende la diferencia operativa entre el sondeo continuo y los eventos reactivos mediante una situación cotidiana.

📢

El Observador Incómodo (window.resize)

Imagina a un empleado de oficina parado junto al termómetro que grita en voz alta cada décima de grado que cambia la temperatura: "¡Hacen 24.1°C!", "¡Hacen 24.0°C!", "¡Hacen 23.9°C!". Interrumpe el trabajo de todos constantemente sin aportar valor.

⚙️

El Termostato Digital (window.matchMedia)

Programas el termostato a 22°C. El dispositivo permanece en absoluto silencio mientras la temperatura fluctúa entre 23°C y 28°C. En el instante preciso en que baja de los 22°C, dispara una señal limpia para encender la calefacción.

1 Consulta directa (.matches): Puedes mirar el display del termostato cuando quieras para saber si la calefacción está activa.
2 Evento puntual (change): Solo se emite un pitido cuando se cruza la frontera de los 22°C, liberando al procesador del resto de fluctuaciones.

  • Cambiar colores, fondos o tipografías.
  • Reorganizar columnas con CSS Grid o Flexbox.
  • Ajustar paddings, márgenes y tamaños.

  • Cargar imágenes de alta definición o datos vía fetch() solo en desktop.
  • Activar escuchas táctiles exclusivas para móviles.

7. Buenas Prácticas y Errores Habituales

Evita las trampas clásicas de sintaxis y compatibilidad para construir código robusto y preparado para producción.

Error Clásico 1

Olvidar los Paréntesis

❌ window.matchMedia("max-width: 768px");
✔️ window.matchMedia("(max-width: 768px)");

Sin paréntesis, la cadena es inválida según la gramática de CSS y matches retornará false de por vida.

Error Clásico 2

Usar el Método Deprecado addListener()

❌ mq.addListener(miFuncion); // OBSOLETO
✔️ mq.addEventListener("change", miFuncion);

addListener() era el método antiguo para Safari e IE. Hoy la especificación unificó a addEventListener("change").

Error Clásico 3

Olvidar la Invocación Inicial

❌ mq.addEventListener("change", handler); // Solo
✔️ handler(mq); mq.addEventListener("change", handler);

Si el usuario nunca redimensiona la ventana, el evento jamás se disparará y la pantalla quedará sin inicializar.

Error Clásico 4

Uso Innecesario para Estilos Simples

❌ elemento.style.fontSize = e.matches ? "14px" : "18px";
✔️ Definir @media (max-width: 600px) en style.css

No utilices JavaScript para lo que CSS puede resolver de forma más veloz, declarativa y limpia.

9. Retos Prácticos y Solucionario Paso a Paso

Resolución comentada de los 3 niveles de ejercicios de la guía de estudio de matchMedia().

Nivel 1 & Nivel 2

Evaluación Inmediata y Escucha de Tema

1. Comprobación de ancho móvil con matches inmediato.
2. Detección reactiva de modo oscuro del sistema con onchange.

// Nivel 1: Detección Inmediata
const mqMovil = window.matchMedia("(max-width: 600px)");
console.log(mqMovil.matches ? "Vista móvil" : "Vista amplia");

// Nivel 2: Escucha de Tema SO
const mqTema = window.matchMedia("(prefers-color-scheme: dark)");
mqTema.onchange = (e) => {
  console.log(e.matches ? "Cambiado a modo oscuro" : "Cambiado a modo claro");
};
Nivel 3: Arquitectura Completa

Navegación Adaptativa Sincronizada

Función que sincroniza clases del DOM con el punto de corte de 992px tanto al inicio como en cada redimensionamiento.

function configurarNavegacionAdaptativa() {
  const mq = window.matchMedia("(min-width: 992px)");
  const actualizar = (e) => {
    document.body.classList.toggle("desktop-nav", e.matches);
  };
  actualizar(mq); // Estado inicial
  mq.addEventListener("change", actualizar); // Reactividad
}
