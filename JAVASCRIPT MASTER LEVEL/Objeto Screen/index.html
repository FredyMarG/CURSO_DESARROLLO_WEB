01 / FUNDAMENTOS DEL BOM

¿Qué es el objeto screen?

window.screen (o simplemente screen) forma parte del Browser Object Model (BOM) y expone propiedades de solo lectura sobre la pantalla física donde se muestra el navegador.

🖥️ Qué SÍ mide

  • Dimensiones del monitor o pantalla del teléfono en píxeles CSS lógicos.
  • Espacio útil disponible para ventanas del sistema operativo.
  • Bits de color y orientación actual del dispositivo.

🚫 Qué NO mide

  • No mide el tamaño de tu pestaña web (para eso existe window.innerWidth).
  • No permite modificar la resolución del monitor (todas sus propiedades son read-only).
02 / DIMENSIONES

width / height vs availWidth / availHeight

dimensiones_screen.js
// Resolución total de la pantalla (ej. 1920 x 1080)
const anchoTotal = screen.width;
const altoTotal  = screen.height;

// Área disponible descontando barra de tareas de Windows / Dock de macOS
const anchoDisponible = screen.availWidth;
const altoDisponible  = screen.availHeight;

// Píxeles reservados por el sistema operativo
const altoBarraSO = altoTotal - altoDisponible;
console.log(`Barra del SO: ${altoBarraSO}px`);
Uso práctico: Cuando abras una ventana emergente con window.open(), usa screen.availWidth y screen.availHeight para centrarla sin que quede tapada por la barra de tareas.
03 / GRÁFICOS Y COLOR

colorDepth y pixelDepth

🎨 screen.colorDepth

Devuelve el número de bits empleados para representar cada color en un píxel. En pantallas actuales suele ser 24 (16.7 millones de colores) o 30 (HDR).

🔬 screen.pixelDepth

Devuelve la profundidad de bits por píxel del búfer de pantalla. En los navegadores modernos coincide prácticamente siempre con colorDepth.

profundidad_color.js
console.log("Bits de color:", screen.colorDepth); // 24
console.log("Bits por píxel:", screen.pixelDepth); // 24
console.log("Colores posibles:", 2 ** screen.colorDepth); // 16,777,216
04 / MÓVILES Y TABLETS

screen.orientation y el Evento change

La API ScreenOrientation informa si el dispositivo está en horizontal (landscape-primary) o vertical (portrait-primary), junto con su ángulo de rotación.

orientacion.js
if (screen.orientation) {
    console.log("Orientación actual:", screen.orientation.type);
    console.log("Ángulo actual:", screen.orientation.angle + "°");

    // Escuchar cuando el usuario gira el teléfono
    screen.orientation.addEventListener("change", (e) => {
        console.log("Cambió a:", e.target.type, e.target.angle);
    });
}
05 / COMPARATIVA CLAVE

screen vs window.innerWidth vs outerWidth

screen.width / heightMonitor físico completoNo
screen.availWidth / availHeightMonitor sin barra de tareas / dockNo
window.outerWidth / outerHeightVentana completa del navegador (con pestañas y bordes)Sí
window.innerWidth / innerHeightViewport visible de tu página webSí
06 / PANTALLAS HIDPI

Píxeles CSS vs Píxeles Físicos (devicePixelRatio)

En pantallas Retina o smartphones modernos, 1 píxel CSS puede equivaler a 2×2 o 3×3 píxeles físicos reales. Multiplicando screen.width por window.devicePixelRatio obtienes la resolución física real del panel.

densidad_hidpi.js
const dpr = window.devicePixelRatio || 1;
const fisicoAncho = Math.round(screen.width * dpr);
const fisicoAlto  = Math.round(screen.height * dpr);

console.log(`CSS Lógico: ${screen.width}x${screen.height} | DPR: ${dpr}x`);
console.log(`Hardware Físico: ${fisicoAncho}x${fisicoAlto}`);
07 / PRODUCCIÓN

Errores Frecuentes y Buenas Prácticas

⚠️ Errores comunes

  • Usar screen.width para diseño responsivo en lugar de window.innerWidth o Media Queries CSS.
  • Intentar modificar propiedades como screen.width = 1024 (son de solo lectura).
  • Asumir que screen.orientation existe sin comprobar compatibilidad.

✅ Buenas prácticas

  • Usa availWidth / availHeight al calcular tamaños seguros de popups.
  • Combina screen.width con devicePixelRatio al dimensionar <canvas> nítidos.
  • Prefiere window.matchMedia() para detectar cambios de viewport y orientación.
