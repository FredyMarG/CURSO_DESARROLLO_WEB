DIAPOSITIVA 2 · FUNDAMENTOS Y ANALOGÍA

¿Qué es Tablas Semánticas y para qué sirve?

🎯 Propósito en proyectos reales

Organiza datos tabulares (horarios, comparativas, facturas) con encabezados accesibles usando <th scope="col"> y combinación de celdas. Entender la intención de cada etiqueta o propiedad te ayuda a escribir código más limpio, accesible y fácil de mantener.

🧠 Modelo mental: Piensa siempre primero en la estructura y el significado (qué rol cumple este elemento para el usuario y los lectores de pantalla) y luego en su apariencia visual con CSS.
DIAPOSITIVA 2 · ESTRUCTURA Y ACCESIBILIDAD

thead, tbody, tfoot y scope

Las tablas deben usarse únicamente para datos tabulares, nunca para maquetar el diseño de una página.

📝 Tabla bien estructurada

<table>
  <caption>Planes del Curso</caption>
  <thead>
    <tr><th scope="col">Módulo</th><th scope="col">Nivel</th></tr>
  </thead>
  <tbody>
    <tr><td>HTML5</td><td>Avanzado</td></tr>
  </tbody>
  <tfoot>
    <tr><td colspan="2">Incluye ejercicios</td></tr>
  </tfoot>
</table>

🔎 Atributos clave

  • scope="col" / scope="row": indica a lectores de pantalla si el encabezado es de columna o fila.
  • colspan="2": una celda ocupa 2 columnas.
  • rowspan="2": una celda ocupa 2 filas.
DIAPOSITIVA 4 · BUENAS PRÁCTICAS

Buenas prácticas y errores comunes en Tablas Semánticas

✅ Buena práctica: Verifica siempre tu código en el navegador con DevTools (F12), prueba la navegación con teclado (Tab) y mantén una estructura semántica clara.
⚠️ Error frecuente: Usar etiquetas o propiedades únicamente por su aspecto visual por defecto, olvidando atributos clave de accesibilidad, contraste o validación.
DIAPOSITIVA 5 · ESPECIFICIDAD Y CASCADA

Cómo decide CSS qué regla gana

Al aplicar Tablas Semánticas, recuerda el orden de prioridad: estilos en línea > ID (#id) > clase/atributo/pseudoclase (.clase) > etiqueta (div). Mantén la especificidad baja usando clases reutilizables.

DIAPOSITIVA 6 · INSPECCIÓN EN DEVTOOLS

Depurando estilos en vivo con el panel Computed

Si una propiedad de Tablas Semánticas no surte efecto, abre DevTools (F12) → pestaña Styles y revisa si aparece tachada o con un ícono de advertencia por valor inválido o conflicto de display.

DIAPOSITIVA 7 · SOPORTE Y COMPATIBILIDAD

Uso progresivo y @supports en navegadores

Antes de usar propiedades modernas en producción, verifica su soporte en Can I Use o envuelve mejoras opcionales dentro de @supports (...) para ofrecer un fallback sólido.

DIAPOSITIVA 8 · ARQUITECTURA MANTENIBLE

Variables CSS y tokens de diseño reutilizables

Combina Tablas Semánticas con variables CSS (var(--espacio-md)) para mantener consistencia visual entre componentes y facilitar temas claro/oscuro.

DIAPOSITIVA 9 · ACCESIBILIDAD VISUAL

Contraste, foco visible y zoom al 200%

Asegúrate de que tus estilos no recorten texto al ampliar el zoom del navegador al 200% y nunca elimines outline sin ofrecer un indicador de :focus-visible claro.

DIAPOSITIVA 10 · CASO DE USO REAL

Patrones de producción con Tablas Semánticas

En proyectos reales, combina Tablas Semánticas con tokens de diseño (--space-*, --radius-*) y clases utilitarias claras para evitar duplicar reglas entre componentes.

💡 Consejo: Mantén tus componentes desacoplados del layout padre para reutilizarlos en cualquier sección.
DIAPOSITIVA 11 · PRUEBAS Y MANTENIMIENTO

Validación visual y checklist de Tablas Semánticas

  • Prueba en anchos de 360px, 768px y 1280px desde DevTools.
  • Verifica contraste y estados interactivos (:hover, :focus-visible).
  • Revisa en el panel Computed que no existan sobrescrituras accidentales.
