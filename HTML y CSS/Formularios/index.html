DIAPOSITIVA 2 · BASE ESTRUCTURAL

Anatomía de <form>, method y name

La etiqueta <form> agrupa controles de usuario para enviarlos a un servidor o procesarlos con JavaScript. El atributo name de cada campo es obligatorio para que los datos tengan clave al enviarse: 

<form action="/registro" method="POST">
  <label for="usuario">Usuario</label>
  <input id="usuario" name="usuario" type="text" required />
  <button type="submit">Enviar</button>
</form>
DIAPOSITIVA 3 · ACCESIBILIDAD (A11Y)

<label>, <fieldset> y <legend>

Nunca reemplaces un <label> por un placeholder: el placeholder desaparece al escribir y los lectores de pantalla necesitan for="id" para anunciar qué pide el campo: 

<fieldset>
  <legend>Método de contacto</legend>
  <label><input type="radio" name="contacto" value="email" checked /> Correo</label>
  <label><input type="radio" name="contacto" value="tel" /> Teléfono</label>
</fieldset>
DIAPOSITIVA 4 · CONTROLES SEMÁNTICOS

Tipos Modernos de <input>

Elegir el type correcto mejora la experiencia móvil (muestra el teclado adecuado) y activa validaciones automáticas del navegador:

date / timeFechas y horasDespliega calendario/reloj nativo

DIAPOSITIVA 5 · LISTAS Y TEXTOS LARGOS

<select>, <datalist> y <textarea>

Usa <select> para listas cerradas, <datalist> para autocompletar sugerencias manteniendo escritura libre y <textarea> para textos multilínea: 

<input list="lenguajes" name="lenguaje" placeholder="Elige o escribe..." />
<datalist id="lenguajes">
  <option value="JavaScript"></option>
  <option value="Node.js"></option>
</datalist>
DIAPOSITIVA 6 · VALIDACIÓN SIN JAVASCRIPT

required, minlength, min/max y pattern

Antes de escribir JavaScript, HTML5 ya bloquea el envío si un campo no cumple las reglas declaradas en sus atributos:

AtributoRegla que aplica
requiredImpide enviar el formulario si el campo está vacío
minlength / maxlengthExige un mínimo o máximo de caracteres
min / maxLimita valores numéricos o fechas válidas
pattern="[A-Za-z0-9]{4,}"Valida contra una expresión regular exacta
DIAPOSITIVA 7 · FEEDBACK VISUAL EN CSS

Estilos en Tiempo Real con :valid y :invalid

Un error clásico es pintar rojo apenas carga la página. Combina :not(:placeholder-shown) con :invalid para mostrar errores solo cuando el usuario ya escribió algo: 

input:not(:placeholder-shown):invalid {
  border-color: #f43f5e;
  box-shadow: 0 0 0 3px rgba(244, 63, 94, 0.25);
}
input:not(:placeholder-shown):valid {
  border-color: #10b981;
}
✨ Estándar moderno (:user-valid / :user-invalid): A diferencia de :invalid, estas pseudoclases solo se activan después de que el usuario interactuó con el campo, evitando mostrar bordes rojos antes de empezar a escribir.
DIAPOSITIVA 8 · EXPERIENCIA DE USUARIO

:focus-within, accent-color y :focus-visible

Con accent-color personalizas checkboxes y radios en una sola línea CSS, y con :focus-within iluminas la tarjeta o etiqueta padre cuando el usuario entra al input: 

input[type="checkbox"], input[type="radio"] { accent-color: #38bdf8; }
.campo:focus-within label { color: #38bdf8; }
button:focus-visible { outline: 2px solid #38bdf8; outline-offset: 2px; }
DIAPOSITIVA 9 · PUENTE CON JAVASCRIPT Y NODE.JS

Leer Todo el Formulario con new FormData(form)

Al conectar el formulario con JavaScript y una API Fetch/Node.js, no hace falta leer cada input uno por uno: FormData recoge todos los campos que tengan atributo name: 

form.addEventListener('submit', async (e) => {
  e.preventDefault();
  const payload = Object.fromEntries(new FormData(form));
  await fetch('/api/registro', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(payload)
  });
});
DIAPOSITIVA 10 · CALIDAD Y SEGURIDAD

Buenas Prácticas y Errores Comunes

Recuerda siempre que la validación en HTML/CSS mejora la experiencia de usuario, pero **nunca reemplaza la validación en el servidor**:

Buena prácticaError que evita
Validar también en el backend (Node.js)Que un atacante salte los atributos HTML desde DevTools
Usar autocomplete="email" / "current-password"Fricción al llenar formularios en móvil y escritorio
Incluir type="button" en botones que no envíanEnvíos accidentales de formularios
